после согласования с пользователем, здесь фиксируется факт.

- 2026-07-26: fake-upstream в conformance — nginx:alpine (не caddy): статики достаточно, образ меньше.
- 2026-07-26: клиент для conformance-сценариев — сервис `client` (curlimages/curl) в compose с profile `tools`, запуск через `docker compose run`.
- 2026-07-26: runtime-образ registry в conformance — alpine (не distroless): нужен wget для healthcheck.
- 2026-07-26: конфиг для `make dev` лежит в `conformance/dev.yaml` (отдельной dev-директории в структуре CLAUDE.md нет).

- 2026-07-26: стораджи регистрируются в реестре (`api.RegisterStorage`), типизированный конфиг конвертируется в options-map через `StorageConfig.Options()`; выбор бэкенда — по имени, без switch в сборке.
- 2026-07-26: пустой `database.dsn` = БД отключена (никакого неявного fallback на PG*-env, чтобы не подключаться «куда-то» молча).
- 2026-07-26: SWR реализован как синхронный refresh с fallback на stale при недоступном апстриме (не асинхронный revalidate) — покрывает инвариант 6, проще в отладке; асинхронность можно добавить позже без смены контрактов.
- 2026-07-26: маршрутизация Bearer-кредов: префикс `reg_` → статический токен, две точки → JWT; иное → 401.
- 2026-07-26: echo-модуль для conformance живёт в `conformance/echomodule` и линкуется в бинарь только под build-tag `conformance` (в проде его нет).
- 2026-07-26: гео-репликация — журнальная федерация (app-level outbox + pull-mesh), НЕ стораджевая репликация и НЕ PG multi-master; ADR в docs/geo-replication.md, реализация — Фаза 7.
- 2026-07-26: конфликт конкурентных публикаций — правило K1 (канон = min sha256 + карантин + 409 + ручной resolve), не LWW по часам; дефолт записи — write-affinity (forward на home_site), active-active publish — opt-in per feed.
- 2026-07-26: audit сайт-локален; token create не реплицируется (репликация не создаёт полномочий), revoke реплицируется по хэшу.
- 2026-07-26: conformance-гейтвей — nginx с self-signed сертификатом registry.local (terraform требует HTTPS для registry-протокола); тестовый приватный ключ закоммичен сознательно, это фикстура.
- 2026-07-26: maven-клиент conformance — образ с запечёнными при docker build плагинами (dependency-plugin по полным координатам) и удалёнными `_remote.repositories`; герметичность уровня «pull базовых образов».
- 2026-07-26: X-Terraform-Get отдаётся абсолютным URL из `site.external_url` — terraform отвергает голые относительные пути («cannot detect a supported module source type»).
- 2026-07-26: terraform-модуль проксирует только HTTP(S)-архивы; VCS-источники (`git::…`, весь публичный registry.terraform.io) → внятный 502: git-операции вне скоупа pull-through HTTP-кэша.
- 2026-07-26: публичного blob-эндпоинта по хэшу нет — он обходил бы цепочку политик и аудит; terraform download указывает на archive-маршрут фида, peer-fetch федерации приедет в Фазе 7 на internal listener'е (ADR).
- 2026-07-26: X-Terraform-Get по умолчанию — `./archive.tar.gz` (относительная форма, резолвится клиентом от download-URL и не требует конфигурации); абсолютный URL из `site.external_url` — если он задан. Голая `archive.tar.gz` terraform'ом отвергается.
- 2026-07-26: аутентификация принимает HTTP Basic (пароль = токен/id_token, username игнорируется) — `mvn`/Gradle с `<server>`-кредами не умеют Bearer; 401 анонсирует обе схемы.
- 2026-07-26: indirect-локации из апстрима фетчатся с SSRF-guard'ом: чужой хост обязан резолвиться в публичный адрес (loopback/RFC1918/link-local/CGNAT/ULA запрещены), редиректы проверяются пóхопно; хост самого апстрима фида доверенный.
- 2026-07-26: go-getter-параметр `?checksum=algo:hex` из X-Terraform-Get становится ожидаемой чексуммой (инвариант 5), `//subdir` — отказ; URL в логах пишется без query (инвариант 12).
- 2026-07-26: формат-модуль может ограничивать набор своих фидов (`api.FeedSetValidator`): terraform запрещает >1 фида на сайт, т.к. service discovery хостовый.
- 2026-07-26: maven-модуль отдаёт .sha256/.sha512 sidecar'ы даже когда апстрим их не публикует — все дайджесты считаются при инжесте и хранятся в манифесте.
- 2026-07-26: кросс-репличный advisory lock деградирует в lock-less ingest при недоступном Postgres (инвариант 7); безопасно из-за идемпотентных контент-адресуемых записей.
- 2026-07-26: hosted-манифесты пишутся ТОЛЬКО через `CoreServices.Publish`; иммутабельность держит unique-констрейнт PG (не advisory lock), S3-манифест — проекция для read-path без БД.
- 2026-07-26: publish-права — не политика, а per-feed список identity-паттернов в YAML (`token:`, `project:` с glob'ами): это авторизация, а не контентная политика.
- 2026-07-26: политики получают зависимости конструктором (`api.PolicyServices`: общий кэш вердиктов + логгер), без глобалов; таблица вердиктов generic — ядро не знает специфики политик.
- 2026-07-26: канонические ключи метаданных (`license`, `published_at`, `ecosystem`) поставляет формат-модуль через `api.MetadataSource`; политики форматов не знают (инвариант 1).
- 2026-07-26: `Reindex` — детерминированная функция множества манифестов (lastUpdated берётся из данных, не из часов); golden-тест «дважды → байт-идентично» защищает гео-инвариант 15.
- 2026-07-26: клиентский `maven-metadata.xml` при deploy принимается и игнорируется — индекс пересобирает Reindex.
- 2026-07-26: conformance-проект для deploy собирается воспроизводимо (`project.build.outputTimestamp`), иначе одинаковый передеплой давал бы разные байты и ложный 409.
- 2026-07-26: npm использует ДЕКОДИРОВАННЫЕ пути (`@scope/pkg`, не `%2f`): так URL к апстриму строится без двойного экранирования, а npm-регистри принимают обе формы.
- 2026-07-26: чексумма tarball'а берётся из `dist.integrity`/`shasum` package root'а через `api.MetadataSource` (новый канонический ключ `checksum`) — инвариант 5 работает и там, где чексумма лежит внутри JSON-метаданных.
- 2026-07-26: Composer dist-URL (произвольный хост, обычно GitHub) кодируется base64url прямо в путь registry (`Intent.RemoteURL`), фетчится с тем же SSRF-guard'ом; относительная база composer'ом не поддерживается, поэтому composer-фид требует `site.external_url` (проверяется валидацией).
- 2026-07-26: NuGet — пути registry вендор-нейтральные (`v3/flat2/`, `v3/registration/`), маппятся на nuget.org-раскладку апстрима (`v3-flatcontainer/`, `v3/registration5-gz-semver2/`); gzip-регистрации распаковываются перед переписыванием URL, клиент получает plain JSON.
- 2026-07-26: NuGet catalog-URL не переписывается — каталог registry не обслуживает, честный passthrough (dotnet restore его не требует).
- 2026-07-26: npm hosting: версии и dist-tags хранятся ОТДЕЛЬНЫМИ мутабельными координатами под зарезервированным префиксом `-/hosted/…` (сегмент `-` протоколом зарезервирован), package root собирается Reindex'ом — это и есть задел под гео (per-tag merge вместо перезаписи всего документа).
- 2026-07-26: unpublish скрывает версию из индекса, блоб остаётся (контент-адресуемые блобы общие, чистит `registry gc`).
- 2026-07-26: Maven SNAPSHOT — timestamped-сборки иммутабельны (артефакты), алиас `-SNAPSHOT` и version-level metadata мутабельны с коротким TTL; retention по умолчанию — 5 последних build-номеров в индексе.
- 2026-07-26: OCI/Docker — свой модуль НЕ делаем: рекомендация ставить Harbor рядом. Протокол OCI (иммутабельные слои по digest + мутабельные теги) архитектурно ложится на существующий пайплайн, но объём (manifest lists, cosign, GC слоёв) не окупается против зрелого Harbor. Пересмотреть только по явному запросу пользователя. — **Пересмотрено 2026-07-29**: запрос был, модуль сделан (Фаза 16, `modules/format/oci`). Оценка объёма оказалась завышенной: протокол лёг на пайплайн как предполагалось, а manifest lists — это обычные артефакты по digest. Не сделано и не требовалось: cosign-подписи (клиент кладёт их как обычные образы) и GC слоёв сверх общего `registry gc`.
- 2026-07-26: redirect-режим — per-feed флаг + двойная проверка возможностей (сторадж умеет presign И формат объявил intent redirect-safe); любой сбой presign → обычный стриминг.
- 2026-07-26: `registry gc` — mark-and-sweep с `-min-age` и advisory-lock'ом на весь прогон; нечитаемый манифест прерывает прогон (лучше не собрать мусор, чем удалить живой блоб).
- 2026-07-26: helm — секреты (S3, DSN) только из Secret'ов, подставляются в конфиг через sed в entrypoint; ConfigMap не рестартит поды (конфиг перечитывается на лету).
- 2026-07-26: конфиг перечитывается только при реальном изменении содержимого (сравнение sha256) — иначе интервальная перечитка писала лог каждые 30 с.
- 2026-07-26: переписывание URL в npm/nuget снимает path-префикс апстрима (апстрим под сабпутём иначе дублировал сегмент в ссылке) — нашёл conformance redirect-сценарий.
- 2026-07-27: гео — журнал в PG (repl_journal) + HLC и sequence из одной залоченной строки: порядок в журнале совпадает с порядком коммитов, пагинация не может пропустить запись.
- 2026-07-27: карантин ключуется по (feed, coordinate, reason) — причины независимы, снятие одной не снимает другую (иначе merge неконвергентен).
- 2026-07-27: конфликт K1 хранится как множество увиденных дайджестов (union строк publish_conflicts), а не пара winner/loser — пара зависит от порядка при трёх и более версиях.
- 2026-07-27: publish форвардится на home-сайт по репликационному каналу (peer аутентифицирован), а не публичным API; identity едет как on-behalf-of и переавторизуется на home.
- 2026-07-27: отзыв токена выселяется из auth-кэша sweeper'ом (auth.revocation_sweep, 5s) — кэш нужен для выживания при падении PG, поэтому отзыв бьёт не мгновенно, а в пределах интервала.
- 2026-07-27: партиция в гео-conformance — отдельная сеть `wan` и `docker network disconnect`, без iptables внутри контейнеров (не требует сети для apk).
- 2026-07-27: 410 на /journal выдаётся, когда oldest > after+1 — включая курсор 0: новый сайт, направленный на подчищенный журнал, обязан бутстрапиться со snapshot, а не молча пропустить историю.
- 2026-07-27: у контрольных вызовов пира (status/journal/manifest) отдельный таймаут 10s — опрос держит межрепличный лиз, и зависший handshake иначе морозил репликацию всего сайта.
- 2026-07-27: NetworkPolicy для internal listener'а обязательна: чарт не рендерится при replication.enabled без peerCIDRs/peerNamespaceSelector.
- 2026-07-27: ревизия Фаз 6–7 (35 подтверждённых находок) — ключевое: ListHosted("", "") не матчил ничего, из-за чего snapshot/repair/backfill молча ничего не делали.
- 2026-07-27: карантин — LWW-регистр с HLC; карантин конфликта снимается резолюцией безусловно (он производное состояние, а стамп детекции у сайтов разный).
- 2026-07-27: резолюция конфликта терминальна — хранится в conflict_resolutions и консультируется каждым последующим merge, иначе поздний publish переоткрывал конфликт.
- 2026-07-27: origin pinning — сайт принимает от пира только его собственный журнал (mesh v1); чужие потоки приходят первыми руками от своего источника.
- 2026-07-27: перенос блоба вынесен за границу транзакции apply (иначе WAN-передача держала row lock hlc_state и морозила publish на сайте).
- 2026-07-27: advisory-локи живут на отдельном соединении, не из пула — иначе держатель лока конкурирует за соединения со своим же fn.
- 2026-07-27: подстановка ${VAR} из окружения делается загрузчиком конфига (не sed в entrypoint): sed портил секреты с `&`/`|`/`\` и убивал hot-reload через одноразовую копию.
- 2026-07-27: токен-кэш отдаёт протухшую личность при недоступной БД (окно 6h, флаг Stale) — иначе падение PG дольше TTL убивало аутентифицированное чтение (инвариант 7); publish на протухшей личности запрещён.
- 2026-07-27: UUID пиров пиннится в БД (repl_peer_identity), а не в памяти процесса — иначе каждая реплика и каждый рестарт решали заново, кто такой пир (инвариант 3).
- 2026-07-27: snapshot несёт активные карантины и хэши отозванных токенов — иначе новый сайт отдавал бы координаты, заблокированные везде, и принимал отозванные токены.
- 2026-07-27: conformance-хелпер `replicated` требует X-Registry-Source: cache; peer-fallback отдаёт те же байты и раньше проходил за «сошлось».
- 2026-07-27: вторая ревизия (21 подтверждённая находка + пробелы) — карантин конфликта стал производным от множества открытых конфликтов координаты (у Maven GAV несколько путей, резолюция одного снимала блок с остальных).
- 2026-07-27: ${VAR} раскрывается ПОСЛЕ парсинга, по скалярам: текстовая подстановка позволяла значению переменной переписать смысл конфига (обход auth).
- 2026-07-27: X-Registry-Peer несёт имя ВЫЗЫВАЮЩЕГО и принимается только если это настроенный пир; иначе ack писался под именем адресата и GC журнала не работал.
- 2026-07-27: `stale_identity_window: 0` действительно отключает fallback (различаем «не задано» и «явный ноль»); протухшая личность отдаётся только при недоступной БД, не при любой ошибке.
- 2026-07-27: gc отказывается мести, пока репликация отстаёт (-ignore-replication-lag для явного продавливания), и защищает обе стороны только НЕзакрытых конфликтов.
- 2026-07-27: ConfigMap чарта собирается как словарь и сливается с extraConfig — текстовое дописывание давало дубль ключа верхнего уровня; smoke прогоняет `registry config check` по всем формам чарта.
- 2026-07-27: интеграционные тесты линтятся и гоняются в CI; property-тест дополнен прогоном настоящего applier'а против реального PostgreSQL и сверкой модели с реализацией.
- 2026-07-27: пересозданный сайт нумерует журнал заново, поэтому пир при смене UUID (trust-reset) или при head < курсора сбрасывает курсор И удаляет свою копию журнала этого origin — иначе новые события отбрасывались как дубликаты и терялись молча.
- 2026-07-27: карантин получил производителя — `registry repl quarantine|release`: без него события quarantine_set/release были недостижимым кодом, а у оператора не было способа снять пакет.
- 2026-07-27: резолюция конфликта делает UPSERT координаты — сайт, поднимающийся со snapshot, узнаёт решение раньше самой координаты, и UPDATE по несуществующей строке молча терял пакет.
- 2026-07-27: покрытие, которого не было: 503 при недоступном home-сайте, конкурентное движение мутабельного dist-tag (HLC-ветка), парковка неизвестного типа события без head-of-line blocking, метрики репликации и digest'ы, падение S3, выборы пуллера (TryLease) и тесты gc.
- 2026-07-27: третья ревизия — snapshot нёс резолюции без размера и чексумм: координата сохранялась с size 0 и отдавалась как пустой 200 при совпадающем sha256 (ни digest, ни projection-repair этого не видят).
- 2026-07-27: перезапуск сайта детектируется по UUID инкарнации в курсоре, а не сравнением номеров — быстро публикующий пересозданный пир проскакивал сравнение.
- 2026-07-27: retention журнала — самостоятельный пол: недостижимый или удалённый пир больше не удерживает журнал вечно, отставший переедет на snapshot.
- 2026-07-27: `repl resync` и `trust-reset` сбрасывают курсор И удаляют копию журнала одной транзакцией — только курсора мало, применение дедуплицируется по (origin, seq).
- 2026-07-27: четвёртая ревизия — эвристика «журнал пира откатился» по номерам убрана: head устаревает во время догоняния, и здоровый журнал мог быть снесён. Перезапуск детектируется только по UUID инкарнации.
- 2026-07-27: retention и ack-обрезка всегда оставляют самую свежую запись origin'а — пустой журнал не может сказать отставшему пиру «ты за горизонтом» (410), и тот молча пропустил бы историю.
- 2026-07-27: bootstrap двигает локальные часы за максимальный стамп snapshot'а — иначе первые собственные записи сайта проигрывали состоянию, которое он только что принял.
- 2026-07-27: отзыв токена — надгробие: применение вставляет строку с revoked_at даже для неизвестного хэша, иначе сайт, получивший этот секрет позже (восстановление, перевыпуск), принял бы отозванный мешем токен.
- 2026-07-27: cross-check bootstrap'а гоняется против ОТДЕЛЬНОЙ базы: общая скрывала, что импортирующий сайт не двигает свои часы (у него был бы общий hlc_state).
- 2026-07-27: по запросу пользователя добавлены Фазы 8–10 (admin API, Web UI, Terraform-провайдер). Инвариант 8 переформулирован: источник правды — один YAML-документ в файле ИЛИ блоб-хранилище, мутации только через API целиком, под локом и с версией; в БД конфигурация по-прежнему не хранится.
- 2026-07-27: UI — React+TypeScript+Vite, встраивается go:embed (выбор пользователя); полная консоль, включая редактирование конфигурации.
- 2026-07-27: конфигурация получила источник `store` (объект в блоб-хранилище) — это то, что позволяет admin API работать при N stateless-репликах; файл остаётся сидом и фолбэком.

- 2026-07-27: если composer.json в архиве и путь загрузки расходятся в имени пакета — отказ. Выбрать одно из двух значило бы опубликовать пакет под именем, которого никто не ждёт.
- 2026-07-27: `ValidateFeeds` у terraform смягчён: несколько фидов допустимы ровно при одной группе, и discovery указывает на группу. Источник модуля называет хост, а не путь, поэтому без группы отдать свои модули и проксируемый реестр с одного адреса физически нельзя.

- 2026-07-27: `Intent.RemoteQuery` — query-строка едет к апстриму и участвует в ключе кэша (хэшем, чтобы произвольный текст не попадал в имя объекта). Без неё прокси-поиск NuGet спрашивал апстрим ни о чём и кэшировал один ответ на все запросы.
- 2026-07-27: поиск — единственное чтение, которое нельзя предгенерировать: индекс перечисляет что есть, поиск зависит от вопроса. Поэтому capability `Searcher` отвечает по запросу из тех же фактов, из которых собран registration — так поиск не может разойтись с restore.

- 2026-07-27: RBAC в стиле Vault: именованные политики, capabilities, явный deny, default deny, привязка bindings'ами к данным аутентификации. Вопрос пользователю о трёх развилках остался без ответа — взяты рекомендованные варианты, они же ниже.
- 2026-07-27: пути правил — объекты реестра (`feed/<фид>/<координата>`, `sys/<область>`), а не URL. URL-пространство затащило бы раскладку каждого формата в ядро (инвариант 1) и заставило бы оператора писать её руками; на координатах правило одинаково читается для фида и для группы, и «публиковать com.example, но не com.acme» вообще выразимо.
- 2026-07-27: старые `anonymous`/`publishers`/`admins` не отменены, а компилируются в те же политики. Две системы прав означали бы два места для ответа на «почему отказ», и рано или поздно они разошлись бы.
- 2026-07-27: матчинг как в Vault — решает самое специфичное правило, а на выбранном уровне deny бьёт всё. Это позволяет «запретить фид целиком, разрешить один namespace внутри»; абсолютный deny запретил бы исключения, и denies просто перестали бы использовать.
- 2026-07-27: deny запрещает ПУТЬ, а не одну capability на нём. «Публиковать нельзя, читать можно» выражается узким grant'ом на чтение, а не частичным deny.
- 2026-07-27: генерируемые политики обязаны быть на одном уровне специфичности. `sys:read` с точным `sys/quarantine` перебивал `sys/*` администратора и лишал его update — поэтому `sys:admin` перечисляет каждую область явно, а не только `sys/*`.
- 2026-07-27: `sys:read` (для любого аутентифицированного) перечисляет операционные области, а не `sys/*`: конфигурация и токены — не статус, и общий grant дал бы любому держателю токена прочитать, кому что разрешено.
- 2026-07-27: публикация проверяется дважды — дешёвый оптимистичный гейт до чтения тела (координата ещё неизвестна) и обязывающая проверка по координате в `CoreServices.Publish`. Оптимистичный гейт не может расширить доступ, только не отказать раньше времени.
- 2026-07-27: `GET /api/v1/access/explain` объясняет решение и умеет отвечать про чужую идентичность (для администраторов). Отказ, который нельзя объяснить, обходят вторым токеном или более широкой политикой — и каждая такая дыра нигде не записана.
- 2026-07-28: у привязки обязательное уникальное имя. Привязку нужно адресовать — управлять поштучно через API, назвать в Terraform, указать на неё в объяснении; безымянную нельзя ни обсудить, ни удалить по отдельности. Сгенерированные из `anonymous`/`publishers` остаются безымянными и помечены `generated`.
- 2026-07-28: способы входа объявляются сайтом (`GET /api/v1/auth/methods`, анонимный) и настраиваются в `auth.methods` с `hidden`. Консоль строит форму из ответа, а не угадывает: реестр без БД не выпускает токенов и не должен предлагать их вводить.
- 2026-07-28: политики и привязки правятся по одной (`/config/access/policies/{name}`, `/config/access/bindings/{name}`), а не переписыванием всего документа — иначе два параллельных apply Terraform затирают друг друга. - 2026-07-28: политику, на которую ещё ссылается привязка, удалить нельзя (409 с именем привязки). Документ бы всё равно не загрузился, но ошибка валидации не говорит, что чинить.
- 2026-07-28: браузерный вход в консоль — authorization code + PKCE, обмен кода делает реестр, а не страница. - 2026-07-28: refresh-токены консоль не запрашивает. Истёкший id_token лечится повторным редиректом, который при живой сессии у провайдера проходит без вопросов, — а refresh-токен в браузере это более сильный креденшл с более длинной жизнью, чем то, что он экономит.
- 2026-07-29: инвентарь фидов считается периодическим обходом стораджа, а не строками в БД. - 2026-07-29: 429 от апстрима — это backpressure, а не отказ. Раньше он попадал в `default` (нерепрайабл) и открывал брейкер: «притормози» превращалось в «фид лежит» для всех клиентов. Теперь — retry с `Retry-After` (капом 30s, иначе апстрим держит соединение клиента сколько хочет) и без счёта в брейкер; 5xx по-прежнему брейкер открывает, для этого он и есть.
- 2026-07-29: npm-тарбол хранится по пути, по которому его спросят, а не под именем вложения. npm загружает `@scope/name-1.0.0.tgz`, а забирает `.../-/name-1.0.0.tgz`; из-за расхождения scoped-пакет «публиковался» успешно и не ставился, а версия парсилась в мусор и уезжала в координату. `versionFromTarball` теперь отказывает вместо того, чтобы вернуть вход целиком.
- 2026-07-29: NuGet-апстрим — корень хоста, а не service index. `https://api.nuget.org/v3/index.json` — это то, что у всех в nuget.config, и джойн путей к нему даёт мусорный URL и 400 без объяснений. Модуль отказывается на загрузке и говорит, что писать вместо; переписывать конфигурацию молча нельзя (инвариант 8).
- 2026-07-29: `available-packages` группы Composer выживает только если его объявили ВСЕ ответившие члены, и тогда это их объединение. Список исчерпывающий: унаследовав его от hosted-члена, группа заявляет, что его содержимое — это всё, и composer отказывается искать проксируемые пакеты («could not be found in any version» для пакета в соседнем члене).
- 2026-07-29: у `make dev` теперь по фиду каждого вида на формат (прокси реального апстрима, hosted, группа над обоими), а не `feeds: []`. Пустой реестр как стенд для разработки бесполезен: половина путей, которые правишь, в нём просто не существует.
- 2026-07-29: `upstream_rps` проставлен во всех конфигах, включая герметичный conformance. Там апстрим локальный и защищать нечего — значение щедрое, — но настройка должна быть покрыта прогоном, а не появляться впервые в проде, когда Central уже отвечает 429.
- 2026-07-29: удалённый сайт делается быстрым не репликацией кэша, а тем, что его прокси-апстримом ставится сайт с внешним каналом. Инвариант 15 при этом цел: через границу по-прежнему не едет ничего производного, B сам решил, где его апстрим. Замерено: холодная сборка на B через A — 53s против 4m20s на A из интернета, при этом A в интернет не сходил ни разу; тёплая — 12s, 1510 из 1510 из кэша.
- 2026-07-29: NuGet-модуль принимает и ту раскладку путей, которую сам просит у апстрима (`v3-flatcontainer/`, `v3/registration5-gz-semver2/`), а не только клиентскую (`v3/flat2/`, `v3/registration/`). Иначе реестр не может быть апстримом реестру — а удалённый сайт, кэширующий через сайт с внешним каналом, это ровно та топология, которую репликация не покрывает (кэш сайт-локален по инварианту 15). Оба написания дают одно намерение, значит одну запись кэша.
- 2026-07-29: `site.external_url` — адрес для клиентов, и он не обязан совпадать с `replication.peers[].public_url`. Первый подставляется в переписанные URL (npm dist.tarball, composer dist.url, terraform X-Terraform-Get), второй — то, по чему пиры ходят друг к другу. Внутрикластерное имя в external_url даёт клиенту ENOTFOUND на скачивании при полностью здоровой репликации.
- 2026-07-29: Helm-модуль берёт имя и версию из `Chart.yaml` внутри архива, а не из имени файла. И имя, и версия могут содержать дефис, так что `nginx-ingress-4.1.0.tgz` разбирается тремя способами и файл не говорит каким. При проксировании архива читать нечего — там эвристика (версия начинается с цифры), и авторитетом остаётся индекс апстрима.
- 2026-07-29: удаление опубликованной версии чарта не поддерживается, хотя ChartMuseum это умеет: инвариант 4. Отказ — 403 с указанием на карантин, а не 404 «нет такого пути», который читался бы как баг клиента.
- 2026-07-29: `Reindex` пропускает фиды, которые ничего не хостят. Раньше проверялось только, умеет ли формат хостинг, — и переконфигурация прокси-фида писала пустой сгенерированный индекс поверх закэшированного апстримного, по тому же ключу, после чего он отдавался как свежий до истечения TTL. Умеет формат — свойство формата; хостит ли фид — свойство фида, и решает второе.
- 2026-07-29: имя фида живёт внутри имени docker-образа (`хост/oci/<фид>/<репозиторий>`), а не в префиксе перед `/v2/`. Клиент строит путь из ссылки на образ и всегда обращается к `/v2/` в корне сайта — точку монтирования некуда поставить впереди. Отсюда `api.FeedRouter`: модуль объявляет корневые пути и говорит, какая их часть называет фид; дальше запрос идёт по обычной цепочке (auth → access → policy → cache → upstream), а не по второй.
- 2026-07-29: тег OCI — мутабельная координата, манифест по digest — иммутабельная. Перевешивание `latest` это протокол по назначению, а не нарушение инварианта 4: релиз, на который тег указывал, остаётся ровно там же и по-прежнему тянется по своему digest. Отказ двигать теги сделал бы реестр непригодным для образов, не защитив ничего.
- 2026-07-29: тег на hosted-фиде читается прямо из опубликованной координаты, а не из сгенерированной копии в `meta/`. Копия была бы вторым источником правды, требовала бы перегенерации на каждый push (O(тегов) записей) и, главное, её пришлось бы перестраивать после репликации; проекция манифеста в сторадже даёт то же самое даром и переживает падение Postgres (инвариант 7). Для этого read-path метаданных на фиде без апстрима сначала смотрит опубликованную координату — форматы, у которых hosted-документ действительно генерируемый, платят за это один Stat раз в TTL.
- 2026-07-29: docker-клиенту отдаётся `WWW-Authenticate: Basic` вместо общего `Basic, Bearer`. Список схем правильно читают maven и gradle; docker берёт первую, для которой у него есть обработчик, и, увидев Bearer, уходит за токеном к realm, которого здесь нет. Возможность `api.AuthChallenger` — на модуль, а не на ядро: имена схем это часть протокола.
- 2026-07-29: `/v2/` (проба API) отвечает 200 всегда и ничего не говорит о том, кто спрашивает. Ответить на неё 401 значит запретить анонимный pull из публичного фида; право читать конкретный репозиторий решается на самом запросе, на фиде, который его держит.
- 2026-07-29: ядро умеет handshake с апстримом, который отвечает 401 и в `WWW-Authenticate` указывает, где взять токен. Это HTTP, а не знание формата: ядро не узнаёт, что такое образ, — только что апстрим отказал и сказал куда идти. Без этого прокси Docker Hub, ghcr и quay не получает вообще ничего. Токены кэшируются в памяти с TTL от выдавшего (производный кэш, инвариант 3) и не логируются (инвариант 12).
- 2026-07-29: media type документа хранится вместе с ним (`PutOpts.ContentType`, `api.MetaContentType`), а не выводится из пути. Один и тот же URL манифеста отвечает то образом, то индексом, и клиент диспатчится по типу; ответ из кэша с `application/octet-stream` — это pull, который падает с «unexpected media type».
- 2026-07-29: сессия загрузки блоба хранится в сторадже под `uploads/<фид>/<репозиторий>/<uuid>/<смещение>`, а смещение для продолжения вычисляется листингом, а не памятью процесса (инвариант 3): любая реплика продолжает начатую другой, рестарт стоит только незавершённых байт. Части удаляются на коммите и на отмене.
- 2026-07-29: манифест, ссылающийся на блобы, которых в фиде нет, отклоняется на публикации (400). Это не образ, а pull, который падает на середине — у всех и навсегда.
- 2026-07-29: пересылка публикации на home-сайт везёт заголовки, описывающие ТЕЛО (Content-Type, Content-Range, Content-Encoding, Content-Disposition, Accept), и не везёт ничего о том, кто публикует. Загрузка при этом принималась, версия появлялась в списке, и ломался только `dotnet restore` на другой стороне: тихая порча ровно того рода, ради которой существует инвариант 5. Кредо клиента по-прежнему не пересекает границу сайта (инвариант 14) — авторизуется on-behalf-of идентичность.
